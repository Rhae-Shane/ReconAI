## 8.3 How accuracy is measured

The generator emits ground-truth labels (`expectedGroupKey`, `expectedStatus`: `MATCHED` | `EXCEPTION`).

`CloseEngine` computes precision/recall on the judged subset against those labels — **match rate is measured, not assumed**.

## 8.4 Adversarial & invariant locks

- `close.test.ts`, `labels.test.ts`, `honesty.test.ts`, `semantic.test.ts`

## 9. Agent design

### 9.1 Philosophy

The agent **narrates, explains, and files exceptions**. It does not invent matches outside FinanceCore tools.

> You are the finance controller. You never guess a match — you assign confidence and file exceptions when unsure. Decisive numbers are computed by the engine, not by you.

### 9.2 Tool surface (all route through FinanceCore)

| Tool | Kind | Module |
| --- | --- | --- |
| `ingestSource` | action | `IngestService` |
| `runReconciliation` | action | `ReconciliationEngine` |
| `judgeCandidates` | decision | Judge (+ optional semantic) |
| `settlementQuery` | read | `SettlementService` |
| `forecastWindow` | read | `CashForecaster` |
| `matchTaxLine` | decision | `TaxMatcher` |
| `fileException` | action | `ExceptionLedger` |
| `closeRun` | terminal | `CloseEngine` |

**Hard rules:**

- Matches / resolutions only via tools
- Every decision returns confidence + reason
- `closeRun` refuses to finalize with unresolved work left silent
- All tools emit audit events

### 9.3 Daily-close narrative (demo)

```text
User: "Close today's books."
  → ingest 4 sources (81 records)
  → exact + normalized + netting
  → judge residual only
  → fileException(unresolved)
  → settlement Q&A + forecast(7) + tax match
  → DONE: 66/81 matched (81.48%), 2 partial, 13 unresolved + report
```
